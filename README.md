# glm-ocr-service

Сервіс з веб-інтерфейсом: завантажуєш зображення в браузері — отримуєш
розпізнаний текст, готовий для копіювання. Під капотом — модель
[glm-ocr](https://ollama.com/library/glm-ocr) через Ollama.

Працює однаково на Raspberry Pi, Mac чи будь-якому Linux-сервері — все запаковано
в Docker, тож переносити на іншу машину = скопіювати папку й запустити `docker compose up`.

## Що всередині

- **`ollama`** — офіційний образ Ollama, тримає модель і віддає інференс.
- **`ocr`** — FastAPI-сервіс, який:
  - на `GET /` віддає веб-сторінку — перетягни/встав/обери зображення,
    натисни «Розпізнати», скопіюй результат кнопкою;
  - на `POST /ocr` приймає файл зображення (той самий ендпоінт, яким
    користується веб-сторінка, — можна викликати і напряму зі скрипта);
  - зменшує зображення до ~1 мегапікселя (за замовчуванням), щоб уникнути
    зациклення моделі — glm-ocr тренували на невеликих зображеннях, і
    завеликі фото/скани викликають `prediction aborted, token repeat limit reached`;
  - ставить потрібні параметри (`num_ctx`, `temperature=0`, `repeat_penalty=1.0`).

## Запуск

```bash
docker compose up -d --build
docker exec glm-ocr-ollama ollama pull glm-ocr
```

Друга команда завантажує модель (~2.2 GB) всередину контейнера `ollama`
один раз; далі вона лишається у volume `ollama-data` між перезапусками.

Перевірка, що все готово:

```bash
curl http://localhost:8000/health
```

## Веб-інтерфейс

Відкрий у браузері `http://<адреса-машини>:8000/` (наприклад
`http://raspberrypi.local:8000/` чи `http://localhost:8000/`, якщо сервіс на
тій самій машині). Далі:

1. Перетягни файл, встав скріншот (Ctrl/Cmd+V) або натисни на область і обери файл.
2. Вибери режим: Текст / Таблиця / Фігура-схема.
3. Натисни «Розпізнати» — за кілька секунд з'явиться текст у полі знизу.
4. Натисни «Скопіювати».

Якщо в `docker-compose.yml` увімкнено `API_TOKEN`, на сторінці є поле для токена
(зберігається лише в браузері, у localStorage).

## Використання без браузера (API)

```bash
curl -X POST http://localhost:8000/ocr \
  -F "file=@/шлях/до/скріншота.png" \
  -F "mode=text"
```

Відповідь:

```json
{
  "text": "розпізнаний текст...",
  "mode": "text",
  "model": "glm-ocr:latest",
  "seconds": 4.2,
  "filename": "скріншот.png"
}
```

### Параметри форми

| Поле | Значення | За замовчуванням |
|---|---|---|
| `file` | зображення (обов'язково) | — |
| `mode` | `text`, `table`, `figure` | `text` |
| `output` | `json` або `text` (звичайний текст без обгортки) | `json` |
| `max_megapixels` | перевизначити ліміт зменшення для одного запиту | `1.0` |

Простий текстовий вивід (зручно для скриптів):

```bash
curl -X POST http://localhost:8000/ocr \
  -F "file=@invoice.png" \
  -F "output=text"
```

## Захист доступу

Якщо сервіс буде доступний ззовні локальної мережі, увімкни токен:
у `docker-compose.yml` розкоментуй `API_TOKEN` і задай значення, тоді
запити мають містити заголовок:

```bash
curl -X POST http://localhost:8000/ocr \
  -H "Authorization: Bearer твій-токен" \
  -F "file=@invoice.png"
```

Без заданого `API_TOKEN` авторизація не потрібна (типово для локальної мережі).

## Перенесення на іншу машину (Pi, Mac, сервер)

1. Постав Docker і Docker Compose (`curl -fsSL https://get.docker.com | sh` на Linux/Pi,
   Docker Desktop на Mac).
2. Скопіюй цю папку.
3. `docker compose up -d --build`, потім один раз `docker exec glm-ocr-ollama ollama pull glm-ocr`.

На слабких платах (Pi 4/5) перший запит буде повільнішим — модель прогрівається.
Наступні запити швидші, бо ваги вже в пам'яті.

## Налаштування продуктивності

Змінні середовища в `docker-compose.yml`:

- `MAX_MEGAPIXELS` — ліміт зменшення зображення (менше = швидше, але гірша якість на дуже дрібному тексті).
- `NUM_CTX` / `NUM_PREDICT` — розмір контексту та максимум токенів відповіді. Для звичайного
  документа/скріншота 2048 токенів більш ніж достатньо; якщо відповідь виправдано довга
  (велика таблиця), піднімай обережно.
- `REPEAT_PENALTY` / `REPEAT_LAST_N` — захист від зациклення. `1.0` вимикає штраф за повторення
  (так рекомендує картка моделі для чистого бенчмарку), але на нетипових зображеннях це
  провокує нескінченне повторення одного фрагмента. `1.15` — компроміс, який зупиняє
  зациклення, майже не шкодячи якості. Якщо зациклення все ще трапляється — піднімай до `1.3`.
- `TEMPERATURE`, `REQUEST_TIMEOUT` — рідко треба чіпати.

## Типові проблеми

- **Розпізнавання "висить" довго (хвилини) і не завершується** — це майже завжди не зависання,
  а зациклення генерації: подивись `docker logs --tail 50 glm-ocr-ollama` — якщо там рахунок
  токенів (`n_gen`) постійно зростає, модель повторює один і той самий фрагмент, поки не
  впреться у `NUM_PREDICT`. Відповідь у такому разі прийде з полем `"truncated": true` і
  попередженням, а у веб-інтерфейсі статус підсвітиться червоним. Причина зазвичай — складне
  чи нетипове зображення (не звичайний документ/скан). Спробуй: зменшити `max_megapixels`
  для конкретного запиту, обрізати зображення до самого тексту без зайвого фону, або
  підняти `REPEAT_PENALTY`.
- **`prediction aborted, token repeat limit reached`** — той самий випадок, тільки Ollama
  сама впіймала зациклення й перервала генерацію раніше.
- **`Could not reach Ollama`** — контейнер `ollama` ще не піднявся або модель не підтягнута
  (`docker exec glm-ocr-ollama ollama pull glm-ocr`).
